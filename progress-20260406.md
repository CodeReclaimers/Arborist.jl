## Cluster 5: CI / docs

**Summary:** Cluster 5 was scoped as "verify deploydocs block + add macOS to CI" — small. Verifying revealed that `docs/make.jl` had a `deploydocs(...)` call configured with `repo = "github.com/CodeReclaimers/Arborist.jl.git"` and `devbranch = "master"`, but **there was no workflow file triggering it**. Only `.github/workflows/{ci.yml,benchmarks.yml}` existed. The docs were configured for deployment but never actually deployed. Worse, running `julia --project=docs docs/make.jl` locally revealed that the docs didn't build at all.

### Three docs build problems found

1. **Two `@ref` cross-references were unparseable.**
   - `operators.md:9` had `[LLM Operator](@ref)` but the section header in `llm_operator.md` is `# LLM Mutation Operator`.
   - `index.md:29` had `[Quick Start guide](@ref)` but the section header in `quickstart.md` is `# Quick Start`.
   - Documenter parses the link text as a Julia expression to look up the binding, so `"Quick Start guide"` became `:(Quick - Start - guide)` and produced the bizarre `"No docstring found for Base.-"` error message — a small but enlightening detail.

2. **`api.md` `@autodocs` blocks only included `Order = [:type, :function]`.** Four documented bindings (`DEFAULT_SAFE_CALLS`, `DEFAULT_TREE_GP_SYSTEM_PROMPT`, `_http_post`, the `Arborist` module docstring) were flagged as missing-from-manual and aborted the build with `:missing_docs`.

3. **After (1) and (2) were fixed, four underscore-prefixed private functions** (`_subtree_crossover`, `_point_mutate`, `_distributed_async_solve`, `_is_valid_statement`) still triggered `:missing_docs` because they had internal docstrings without being included in any `@docs` block. The fix was to add `checkdocs = :exports` to `docs/make.jl` so Documenter only validates exported names. Internal docstrings stay as in-source documentation without polluting the rendered API page.

### Fixes

- **`docs/src/operators.md`** — `[LLM Operator]` → `[LLM Mutation Operator]`.
- **`docs/src/index.md`** — `[Quick Start guide]` → `[Quick Start]`.
- **`docs/src/api.md`** — Rewrote with separate Module / Core Types / Functions / Constants sections. Each `@autodocs` block has a `Filter` clause that excludes underscore-prefixed bindings from the rendered output. (The `Filter` clauses are not what catches the missing-docs check — `checkdocs = :exports` does that — but they keep the rendered API page clean of internals.)
- **`docs/make.jl`** — Added `checkdocs = :exports`.
- **`.github/workflows/docs.yml`** — New workflow using `julia-actions/julia-docdeploy@v1`. Triggers on push to master, tag pushes, and pull requests. Expects the `DOCUMENTER_KEY` secret per the post-registration step list in CLAUDE.md (the secret can be set later; the workflow file just needs to exist now so there's something to trigger when the secret is added).
- **`.github/workflows/ci.yml`** — Added `macos-latest` to the test matrix.
- **`.gitignore`** — Added `docs/build/` (Documenter build output).

### Key takeaway

The Documenter setup was load-bearing broken — `deploydocs(...)` was configured but had no triggering workflow, so nobody had ever run it, so nobody had noticed that it didn't build at all. This is exactly the kind of latent failure that the cluster 5 verification step was designed to catch. Worth the time investment — without it, the first push after tagging v0.1.0 would have produced an immediate, embarrassing CI failure.
