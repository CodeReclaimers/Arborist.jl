# Progress Log — 2026-04-15

## Switch canonical NSGA-II bin packing experiment to 2 objectives

### Motivation

The 2026-04-14 ablation study (`progress-20260414.md`) found that the
third `success_rate` objective in the NSGA-II bin packing experiment
was redundant given `failed_placements`: `two_objective` matched the
3-objective baseline best fitness within 10⁻⁴ (1.0686 vs 1.0687)
while producing a cleaner Pareto front (zero-failed-placements cluster
at fitness 1.1329 vs 1.9674) and a meaningful hypervolume trajectory
(~799 mid-run vs stuck at 0.0 for 3 objectives). The recommendation
was to switch the canonical formulation to 2 objectives. Initial
review summary mis-named it as "fitness + success_rate" — Alan
caught the error; the correct pair is `(fitness, failed_placements)`.

### Files modified

- **`examples/bin_packing.jl`** — `BPMultiObjectiveEvaluator` now
  returns `[fitness, failed_placements]` (dropped the
  `-aux.success_rate` axis). Updated the `evaluate_multi` fallbacks,
  `objective_names`, and the docstring to cite the 2026-04-14 finding.
- **`examples/run_nsga2_ablations.jl`** — structural refactor of the
  ablation set around the new canonical:
  - Deleted `BPTwoObjectiveEvaluator` and its `_nsga2_init_population`
    override (superseded by the updated `BPMultiObjectiveEvaluator`).
  - Added `BPThreeObjectiveEvaluator` with its own behavioral-init
    override so the historical 3-objective baseline remains
    reproducible.
  - Replaced the `two_objective` ablation with a `three_objective`
    ablation (inverted polarity).
  - Updated `BPRandomInitEvaluator` to the new 2-objective formulation
    so the `no_behavioral` control still matches the canonical.
  - Updated `ABLATION_NAMES`, `run_ablation` dispatch, and every
    per-runner banner that listed the old objective triple.
  - Updated the file header to describe the new baseline.
- **`examples/run_nsga2_unseeded.jl`** — updated the header comment to
  describe the 2-objective formulation and cite the ablation study.
  No code change needed; `BPMultiObjectiveEvaluator` is imported and
  picks up the new behavior.
- **`CLAUDE.md`** — added a new NSGA-II bin-packing paragraph under
  the existing `NSGAII` entry documenting the canonical
  `(fitness, failed_placements)` formulation and pointing to the
  `three_objective` ablation for historical reproducibility.

### Decisions and rejected alternatives

- **Kept the `BPMultiObjectiveEvaluator` name** rather than renaming
  to `BPTwoObjectiveEvaluator`. The name still fits (it's a
  multi-objective evaluator, just with 2 objectives rather than 3),
  and keeping it avoids a breakaway rename in `run_nsga2_unseeded.jl`
  and any future consumer.
- **Preserved the historical 3-objective baseline as an ablation**
  rather than deleting it outright. The 2026-04-12 `afae36b` "Best
  Fit from scratch" result was recorded under the 3-objective
  formulation; keeping `BPThreeObjectiveEvaluator` + the
  `three_objective` ablation means that prior result stays
  reproducible even though it is no longer the canonical.
- **Updated `BPRandomInitEvaluator` rather than leaving it at 3-obj.**
  Its only caller is the `no_behavioral` ablation, which exists to
  isolate the contribution of behavioral initialization against the
  canonical. Keeping it at 3-obj would have conflated the
  `no_behavioral` delta with the objective-count delta.
- **Did not rename `BPMultiObjectiveEvaluator` → `BPCanonicalEvaluator`
  or similar.** The name is accurate; adding an adjective only to
  signal the post-ablation decision would be rename-churn without
  semantic benefit.

### Reproducibility note

## Stricter neutral prompt + primitive rename to "container"

### Motivation

The 2026-04-14 ablation pinned the Best-Fit hint as load-bearing
(`neutral_prompt` reached 1.2313, vs baseline 1.0687). Two follow-up
concerns from yesterday's "next steps":

1. The previous `BP_NEUTRAL_SYSTEM_PROMPT` still scaffolded the
   scan-and-check pattern: it described `bp_n_bins()` as defining a
   1-indexed iteration range, told the LLM that `bp_bin_remaining(i)`
   returns 0.0 past the end (an iterate-past-end-to-detect-end hint),
   spelled out that `bp_n_bins()+1` opens a new bin, and warned that
   "failed placement calls incur a fitness penalty" (a check-before-
   placing nudge). The primitives were also ordered by intended use
   (count → inspect → place), reading as an algorithm outline.
2. The function names themselves (`bp_*_bin`) carry "bin packing"
   training-data signal. To test independent inventive capacity
   cleanly, we wanted to disrupt that retrieval cue.

### Code changes

- **Renamed 3 LLM-visible primitives** (40+ occurrences across
  `examples/bin_packing.jl` and `examples/run_nsga2_ablations.jl`):
  - `bp_n_bins` → `bp_n_containers`
  - `bp_bin_remaining` → `bp_container_remaining`
  - `bp_place_in_bin` → `bp_place_in_container`
  Internal Julia names left alone (`BinPackingEvaluator`, file
  `bin_packing.jl`, `BPAuxMetrics.bins_queried`,
  `bin_packing_function_set()`) — none are LLM-visible.

- **`BP_LLM_SYSTEM_PROMPT`** updated to use "container(s)" in the
  natural-language sections so it stays consistent with the renamed
  primitives. The Best-Fit hint sentence preserved verbatim ("scans
  the open containers and picks the one whose remaining capacity
  best matches the item size") to keep the baseline retrieval signal
  intact.

- **`BP_NEUTRAL_SYSTEM_PROMPT`** rewritten from scratch:
  - Reframed as a "packing task" with "containers" of "uniform
    capacity" — minimal domain vocabulary.
  - Primitive listing reduced to **signatures only**, alphabetized
    (`bp_capacity`, `bp_container_remaining`, `bp_item_size`,
    `bp_n_containers`, `bp_place_in_container`).
  - Explicit instruction to the LLM: "their semantics are for the
    program to discover through the objective."
  - Removed: the indexing convention, the "open new bin via index
    n+1" trick, the "returns 0.0 past the end" hint, the failed-
    placement penalty warning, and the word "scanning."

### Smoke-test verification

- `julia --project=. examples/run_nsga2_ablations.jl` (no args) →
  ablation list now reads
  `no_llm, no_llm_extended, no_behavioral, three_objective, pop100, pop50, llm_only, llm_only_neutral, neutral_prompt`.
- `bin_packing_function_set()` registers
  `bp_n_containers, bp_capacity, bp_place_in_container, bp_container_remaining, bp_item_size`
  alongside the arithmetic primitives — confirms rename consistent.
- Trivial program `result = bp_place_in_container(bp_n_containers() + Int32(1))`
  compiles and evaluates to objectives `[2.02, 0.0]` (always-open-
  new-bin → maximum container count, zero failed placements). The
  primitives still drive the same simulator behavior.

### Rejected alternatives

- **Rename internal struct/file names too** (e.g.
  `BinPackingEvaluator` → `ContainerPackingEvaluator`,
  `examples/bin_packing.jl` → `examples/container_packing.jl`).
  Rejected: zero LLM-visibility benefit, large blast radius into
  test files, historical result `.md` files, and prior
  `--experiment=` modes. The rename was scoped to exactly what the
  LLM sees.
- **Keep "bins" terminology in `BP_LLM_SYSTEM_PROMPT` natural
  language and only rename the function names.** Rejected:
  inconsistent vocabulary between primitives and prose would
  confuse the LLM more than it would preserve corpus retrieval.
  The hint sentence still describes Best Fit semantically; the
  word "containers" doesn't break that retrieval.

## Extended ablations: no_llm @ 1000 gen and llm_only_neutral @ 200 gen

### Motivation

Two questions from yesterday's "next steps":
- **Accelerate vs unlock.** Does the LLM merely accelerate
  convergence (so pure GP would eventually reach the same region
  given enough generations), or does it unlock new regions of
  solution space that pure GP cannot reach at all?
- **Independent inventive capacity.** With no Best-Fit hint and no
  classical operators tuning constants, can qwen3-coder:30b
  rediscover a Best-Fit-quality heuristic from primitives alone?

### New ablations added to `run_nsga2_ablations.jl`

- `no_llm_extended`: reuse `run_no_llm` with `generations=1000`
  (added a `generations::Int=200` keyword to `run_no_llm`).
- `llm_only_neutral`: new runner combining
  `mutation_ops=[TrackedMutation(llm_op)]` (LLM-only, like
  `llm_only`) with `system_prompt=BP_NEUTRAL_SYSTEM_PROMPT`.

### Results (canonical 2-obj formulation, seed=42)

| Run | Wall time | LLM calls | Best fitness | Notes |
|---|---|---|---|---|
| `no_llm_extended` (1000 gen) | 1857s | — | **1.321** | hypervolume frozen at 1785.65 from gen ~992 |
| `llm_only_neutral` (200 gen) | 15451s | 12,448 (99.9% success) | **1.3331** | hypervolume stuck at 0.0 throughout |

Reference points (from yesterday's 2026-04-14 ablations):
- `baseline` (hint + LLM + classical, 200 gen, 3-obj): **1.0687**
- `neutral_prompt` (no hint, LLM + classical, 200 gen, 3-obj): 1.2313
- `llm_only` (with hint, LLM-only, 200 gen, 3-obj): 1.3261
- `no_llm` (with classical only, 200 gen, 3-obj): 1.2489

### Findings

**1. LLM unlocks rather than accelerates.**
`no_llm_extended` plateaued at 1.321 with hypervolume frozen for the
last 8+ generations. Top programs have *no* control flow at all
(`has_while: no, has_if: no`). At 5× the generation budget, pure GP
is still ~25% worse than the LLM-assisted baseline of 1.0687 and
shows no signs of structural innovation. Best Fit is not on a
trajectory pure GP can reach.

**2. Without the Best-Fit hint, LLM-only matches pure-GP performance.**
`llm_only_neutral` reached 1.3331 — within 1% of `no_llm_extended`'s
1.321 and *worse* than `llm_only` with the hint (1.3261). The 12,448
LLM calls (99.9% syntactic success) bought essentially nothing beyond
what classical mutation alone achieves. The LLM does *not* invent the
bin-scanning loop independently.

**3. The LLM's "best" neutral-prompt program is first-fit-on-the-last-bin.**
The top `llm_only_neutral` program reads:
```julia
__temp_1 = bp_n_containers()           # ← only the LAST container
__temp_2 = bp_item_size()
__temp_4 = bp_container_remaining(__temp_1)
if __temp_2 <= __temp_4
    bp_place_in_container(__temp_1); break
else
    __temp_1 = __temp_1 + 1
    bp_place_in_container(__temp_1); break  # opens new container
end
```
This queries exactly one container (the most recently opened) and
either places there or opens a new one. The iteration that would
make this Best Fit (or even First Fit) is missing entirely. The
control-flow shell is correct (`while true ... break`) but the
ranging logic the LLM should have invented is replaced by a single
index lookup.

**4. Suspected confound: `success_rate` may have helped pure GP.**
The 2026-04-14 `no_llm` (3-obj) reached 1.2489 in 200 gen; today's
`no_llm_extended` (2-obj, 1000 gen) plateaued worse at 1.321. The
`-success_rate` axis may have been a diversity source that classical
GP relied on, even though it was redundant for LLM runs. Worth
flagging but not actionable — the canonical is configured for the
LLM experiment, not for tuning pure-GP plateau height.

### Decision

The "Best Fit from scratch" framing of the 2026-04-12 result
(`afae36b`) is decisively wrong: the LLM is retrieving Best Fit from
the natural-language hint in the system prompt, not synthesizing it
from problem structure. With the hint replaced by a stricter neutral
prompt and the primitive names renamed to disrupt retrieval, the
LLM's contribution drops from "discovers Best Fit (1.0687)" to "first
fit on the last bin (1.3331)." This should be the headline
correction in any future write-up.
