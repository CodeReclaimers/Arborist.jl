## Decisions and rationale

- **Scope of rerun: LLM + matching classical control, not full
  overnight suite.** The parser/prompt fix only changes behavior in
  code paths that go through `LLMMutationOperator`. Re-running the
  classical, behavioral, and template-baseline experiments would burn
  ~3.5 hr of CPU on identical numbers. Including one fresh
  `extended_classical` run keeps the head-to-head comparison
  internally consistent (same compiler version, same Julia minor, same
  Arborist commit) at near-zero added cost — G1A is CPU-only and
  finishes in ~10 min, far less than G2C's ~3.5 hr critical path.
- **Archive vs. overwrite.** The `progress-20260325.md:274` caveat is
  the entire reason for this rerun: pre-fix LLM data was collected
  under a parser that silently discarded control flow, and "did the
  fix matter" can only be answered by side-by-side comparison.
  Rummaging through git history for the old TSVs would be friction;
  the local-only archive directory is the right tradeoff (preserved
  but not committed).
- **Prompt phrasing — explicit allowed surface vs. open-ended.** The
  rewritten `DEFAULT_GP_SYSTEM_PROMPT` enumerates the allowed forms
  (`while`, `if`/`elseif`/`else`, `for`, `break`, `continue`,
  primitive calls) rather than just saying "any Julia." This is
  deliberate: the parser's `_is_valid_statement` accepts exactly that
  set, and the sanitizer rejects everything else. Telling the LLM
  "any Julia" would invite output that the deserializer would silently
  drop, recreating the very problem the rerun is meant to fix.
- **No `BP_LLM_SYSTEM_PROMPT` change.** That prompt was already
  control-flow aware. The pre-fix bug was *parser-only* for the
  bin-packing example specifically. The rerun therefore exercises
  exactly one variable (parser fixed → LLM control flow now survives
  to evaluation) rather than confounding parser and prompt changes.
