# Progress Log — 2026-04-14

## Ablation study of the NSGA-II Best Fit discovery experiment

### Motivation

The 2026-04-12 result (commit `afae36b`) reported that NSGA-II with
three trace-derived objectives (fitness, -success_rate,
failed_placements) discovered the Best Fit algorithm from unseeded
random initialization in 200 generations, with best fitness 1.0687
exactly matching the Best Fit heuristic baseline. Before building on
that result, we wanted to attribute the win to the right mechanism.
Seven ablations, all at 200 generations and seed 42, were designed to
disentangle the contributions of the LLM, behavioral initialization,
each objective, population size, and the Best Fit hint in the system
prompt.

### Ablation design

| Flag | What changes |
|---|---|
| `no_llm` | Remove the LLM mutation operator; replace with a second `SubtreeMutation` so the mutation-op list stays length-5 |
| `no_behavioral` | Replace behavioral 10k-pool init with 3-random-assignment init (default `_nsga2_init_population`) |
| `two_objective` | Drop success_rate; objectives are (fitness, failed_placements) |
| `pop100`, `pop50` | Same baseline, population reduced to 100 and 50 |
| `llm_only` | Mutation ops set to `[TrackedMutation(llm_op)]` only — no classical operators |
| `neutral_prompt` | Replace the Best Fit–hinting sentence in `BP_LLM_SYSTEM_PROMPT` with a neutral goal statement ("pack the maximum number of objects in the minimum number of bins") |

Critical reason for `neutral_prompt`: the baseline system prompt
contained "*A good heuristic scans the open bins and picks the one
whose remaining capacity best matches the item size (minimizing wasted
space)*" — a natural-language description of Best Fit that Alan had
intended to remove. This ablation directly tests whether the LLM is
synthesizing a solution from problem structure or pattern-matching
the hint.

### Results

All 7 ablations completed cleanly (rc=0). Total wall time 7h 52m.

| Ablation | Wall time | Best fitness | Pareto front | Top `if` | Top `while`/`for` | Δ vs 1.0687 |
|---|---|---|---|---|---|---|
| **Baseline** (prior run, reference) | 3092s | **1.0687** | 200 | yes | for | — |
| `no_llm` | 337s | 1.2489 | 200 | yes | partial | +0.180 |
| `no_behavioral` | 3502s | 1.5934 | 200 | mostly no | no | +0.525 |

| `neutral_prompt` | 3218s | 1.2313 | 200 | no | no | +0.163 |

### Key findings

**1. The Best Fit hint in the system prompt was load-bearing.**
`neutral_prompt` reached only 1.2313, essentially the same ballpark
as `no_llm` (1.2489). Removing the one natural-language sentence
describing the Best Fit strategy erased nearly all of the LLM's
contribution. qwen3-coder:30b at temperature 0.7 was not inventing
Best Fit from problem structure — it was retrieving it from the
prompt. This is the cleanest confirmation that the "discovered from
scratch" framing in the prior result was over-credited to the LLM.

**2. `success_rate` is redundant given `failed_placements`.**
`two_objective` produced 1.0686 (matching baseline to within 10⁻⁴)
with a cleaner Pareto front: the zero-failed-placements cluster sits
at fitness=1.1329 instead of the baseline's 1.9674. Hypervolume is
also meaningful with 2 objectives (~799 mid-run, climbing) where it
was stuck at 0.0 for 3 objectives due to the reference point issue.
Recommendation: switch the canonical experiment to the 2-objective
formulation.

**3. `llm_only` is *worse* than baseline despite 5× the LLM calls.**
12,339 LLM calls over 15,568s (4h 20m) yielded 1.3261 — worse than
the baseline's 2,461 calls over 3,092s. Also notable: LLM success
rate fell to 90.8% (11,207/12,339) vs baseline 98.7%. Without
classical operators tuning constants and indices in LLM-produced
programs, the population cannot iteratively refine near-solutions;
each LLM call replaces the parent wholesale. Classical operators are
providing micro-adjustments the LLM cannot do reliably.

**4. Population size matters; the threshold is between 100 and 200.**
`pop100` (1.3331) and `pop50` (1.3270) both plateaued around 1.33,
roughly twice the gap to baseline that `no_llm` suffered. The full
200-size Pareto front was carrying enough intermediate stepping
stones for the climb from init fitness (~1.9) down to 1.0687.

**5. Behavioral initialization is essential.** `no_behavioral`
collapsed to 1.5934 with top programs having no control flow at
all — just flat assignments. The 10k-pool behavioral seeding
provides starting structure that neither NSGA-II crowding nor LLM
mutation can substitute for.

### Attribution analysis

The 1.0687 baseline result decomposes as:
- **Behavioral init + pop 200**: the scaffold that carries the
  population through the hard middle of evolution (dropping either
  costs ≥0.25 fitness)
- **Best Fit hint in system prompt**: the target (removing it costs
  ~0.16 fitness, leaving only pure-GP performance)
- **LLM + classical operators in combination**: delivery mechanism
  (LLM alone or classical alone both cost ~0.18–0.26)
- **success_rate objective**: not contributing (removing it costs
  0.0001)

### Rejected alternatives during design

- **Matching wall-clock budget for `no_llm`** — rejected. Holding
  generations=200 isolates the effect of the LLM per-generation
  rather than conflating it with compute budget. A future ablation
  could run `no_llm` for 2000+ generations to test whether extra
  iterations close the gap.
- **Running each ablation on 5 seeds** — rejected for this first
  pass. Single-seed results are informative given the large gaps
  (>0.15 fitness) between conditions; multi-seed can follow if any
  margin becomes tight.
- **Combining `llm_only` + `neutral_prompt`** — not in this batch
  but would be the cleanest test of whether the LLM can invent Best
  Fit from scratch without either classical operator support or a
  hinting prompt. Expected outcome: worse than 1.33.

### Implementation notes

- Baseline `examples/run_nsga2_unseeded.jl` had a latent bug: the
  call to `Arborist.create_harness(best.state, checked_body)` at
  line 104 was missing the required `func_name` argument. It
  crashed post-evolution while printing the best program. The
  crash happened *after* evolution completed, so the fitness table
  was still printed — this is how the 1.0687 result was captured.
  Fixed in `examples/run_nsga2_ablations.jl` (pass `gensym("bp_best")`).
- `BPTwoObjectiveEvaluator` needs its own `_nsga2_init_population`
  override because the dispatch key in `bin_packing.jl:348` is
  specifically `BPMultiObjectiveEvaluator`. Without the override,
  the 2-objective ablation would have silently used random init
  instead of behavioral init — and we wouldn't have been able to
  attribute any fitness gap correctly.

### Next steps

- **Publish `neutral_prompt` prominently.** It's the most important
  result for scientific honesty about the prior "from scratch" claim.
- **Switch canonical experiment to `two_objective`.** Identical best
  fitness, simpler formulation, informative hypervolume.
- **Consider running `no_llm` for longer** (1000+ generations) to
  distinguish "LLM accelerates" from "LLM unlocks new regions." The
  337s completion time makes this cheap.
- **Consider `llm_only + neutral_prompt`** to test LLM's independent
  inventive capacity on this benchmark.
- **Rewrite the system prompt** more carefully before any future
  "from scratch" claim. The current `BP_NEUTRAL_SYSTEM_PROMPT`
  still describes the API primitives in a way that makes the
  scan-bins-and-check-capacity pattern almost prescriptive; a
  stricter neutral prompt would describe only the item/bin domain
  and let the LLM infer which primitives to call.
