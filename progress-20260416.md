## Ultrareview follow-up: fix 2-obj migration stragglers in unseeded runner,
## ablation driver, and §2.9 caption

### Summary

`/ultrareview` on master surfaced three loose ends from the 2026-04-15
canonical-objective migration (2-obj `(fitness, failed_placements)`).
Applied all three fixes in this session.

### Files modified

- **`examples/run_nsga2_unseeded.jl`** — banner and Top-10 / Top-5
  display block had been left in the old 3-objective form while the
  header comment was updated to 2-obj. The display code indexed `f[3]`
  at lines 87, 91, 99 against what is now a length-2 fitness vector,
  so the script would crash with `BoundsError` *after* the full
  200-generation NSGA-II + LLM solve completed — full run cost paid,
  no summary printed. Mirrored the `n_obj == 2` branch already present
  in `run_nsga2_ablations.jl`'s `print_results`: dropped the
  `success_rate` column, switched failed_placements to `f[2]`, updated
  banner to "2 objectives / fitness, failed_placements".

- **`examples/run_all_ablations.sh`** — `ABLATIONS` array was out of
  sync with the Julia-side `ABLATION_NAMES`: referenced the retired
  `two_objective` (now `three_objective`) and omitted the new
  `no_llm_extended` and `llm_only_neutral` ablations. Of the 9
  ablations defined in Julia, the driver would run 6, log 1 FAILED
  (`two_objective` → `exit(1)` via unknown-ablation branch; `set -e`
  is deliberately off), and silently skip 2. Updated to
  `(no_llm no_llm_extended no_behavioral three_objective pop100 pop50
  llm_only llm_only_neutral neutral_prompt)` and added a sync note in
  the header comment.

- **`arborist_paper_observations.md`** — §2.9 summary-table caption
  said "canonical 2-objective NSGA-II" but 4 of 6 rows (including the
  headline `1.0687` baseline that §2.10 regime 3 treats as the
  reference) are explicitly labeled `(3-obj)`. Replaced the caption
  qualifier with "objective count per row" and added a one-line note
  that the 3-obj rows remain comparable because the 2026-04-14
  ablation showed best-fitness agreement within 10⁻⁴. Also updated
  §2.10 regime 3 to flag the 3-objective provenance of the `1.0687`
  baseline inline.

### Decisions and alternatives considered

- **bug_006 fix approach.** Two options were on the table: (a)
  lightweight editorial change — drop the "canonical 2-objective"
  qualifier, add a comparability note; or (b) re-run the four 3-obj
  rows under the 2-obj canonical so all rows share a single
  configuration. Chose (a) because the 2026-04-14 ablation already
  established that 2-obj and 3-obj agree on best fitness within 10⁻⁴,
  so re-running would consume significant LLM compute to produce
  numerically indistinguishable rows. The editorial note preserves
  scientific honesty without sunk-cost recollection.

- **bug_005 fix approach.** Considered deriving the `ABLATIONS` shell
  array at runtime from `ABLATION_NAMES` via a one-shot Julia invocation
  to eliminate the hand-maintained duplication. Rejected: the Julia
  script calls `main()` on load, so extracting the constant cleanly
  would require a non-trivial refactor. A static list plus the new
  header-comment sync note is low-risk and keeps the driver readable.

- **bug_001 — did not extract `print_results` into a shared helper.**
  Could have factored the display logic out of both runners into a
  module. Deferred: the unseeded runner has slightly different
  post-print sections (best program + fewest-failed-placements
  program + LLM stats) that don't cleanly match the ablation runner's
  flow. Duplicating the 2-obj print block is simpler today and the
  right abstraction will be clearer once a third caller appears.
