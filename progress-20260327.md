# Progress Log — 2026-03-27

## Lorenz attractor recovery benchmark

### Summary

Implemented the Lorenz attractor recovery benchmark from §9 of the original design plan. This is a symbolic regression problem on a chaotic dynamical system — given trajectory data from the Lorenz equations, recover the derivative expressions from numerical data alone. Uses TreeGenome (DynamicExpressions.jl) for fast vectorized evaluation.

### Data generation

- **RK4 integration** (4th-order Runge-Kutta) at dt=0.005, 2000 steps from (1,1,1)
- Standard Lorenz parameters: σ=10, ρ=28, β=8/3
- Central-difference numerical derivatives, subsampled to 100 training points
- **Normalized derivatives** — divided by standard deviation so MSE of predicting zero ≈ 1.0, making fitness thresholds interpretable regardless of trajectory parameters

### Three sub-benchmarks

| Component | True expression | Difficulty | Convergence (< 0.1) | Best fitness | Assertion |
|-----------|----------------|------------|---------------------|--------------|-----------|
| dx/dt | σ(y - x) = 10y - 10x | Linear combination | 4/5 seeds | 0.0 | ≥3/5 |
| dy/dt | x(ρ - z) - y = 28x - xz - y | Cross-term xz | 2/5 seeds | 0.0743 | ≥2/5 |
| dz/dt | xy - βz = xy - 2.667z | Cross-term xy | 2/5 seeds | 0.0006 | ≥2/5 |

### Design decisions

**RK4 instead of forward Euler.** Original implementation used Euler at dt=0.001. Alan requested RK4 at dt=0.005 — 5x fewer steps for the same trajectory length with O(h⁴) accuracy vs O(h). The larger time step covers 10 time units of trajectory (vs 2 with Euler), giving more dynamic range in the training data.

**Normalized derivatives.** With the longer RK4 trajectory, raw derivative variance was 745–2698. An MSE threshold of 1.0 would be trivially easy (just predict the mean). Normalizing by std makes fitness < 0.1 mean "explains >90% of variance" — a meaningful threshold that's consistent with the Koza benchmarks.

**Tiered convergence requirements.** dx/dt (linear) requires ≥3/5 seeds at fitness < 0.1. The cross-term components (dy/dt, dz/dt) require ≥2/5 — these are genuinely harder because the function set must discover multiplicative cross-terms (xz, xy) from {+, -, *, /, abs}.

**Inline `_std` helper.** Statistics.jl is a stdlib but wasn't in the test environment's Project.toml. Rather than adding a dependency for one function, computed std inline.

## Lorenz recovery example + TreeGenome promoted to core

### Lorenz example

Created `examples/lorenz_recovery.jl` — a standalone, stripped-down version of the Lorenz benchmark intended as a code example. Uses Euler integration (simpler than the RK4 benchmark) for data generation. Shows:
- The true Lorenz equations alongside the GP-discovered expressions
- Fit statistics per component: MSE, RMSE, R-squared, max error, node count
- Expression truncation for readability (cap at 200 chars)
- Bloat penalty (0.005) to encourage simpler expressions
- CLI args: `--seed`, `--generations`, `--pop_size`

Typical output with 500 generations: dx/dt R²=0.9999, dz/dt R²=0.999, dy/dt R²=0.94 (hardest cross-term).

## Code quality audit and test coverage expansion

### Overview

Conducted a comprehensive code quality audit covering all files in `src/`, `ext/`, and `test/`. Measured test coverage (78.7% overall, 1861/2365 lines), identified and fixed 5 defects, and added 290 new test assertions covering previously untested features.

### Defects found and fixed

**1. `_is_valid_call` field name typo — LATENT BUG** (`src/genome/expr_genome.jl:322`)
- Code accessed `state.fset.functions` but GenState has no field `fset`; the correct path is `state.funcs.funcs` (GenState.funcs is a FunctionSet, FunctionSet.funcs is Set{FunctionDetails}).
- **Impact:** All standalone function calls in deserialized code were silently rejected. The `_is_valid_statement` dispatcher for `:call` head always threw a FieldError, which was caught by the caller's try/catch and treated as "invalid statement."
- **Root cause:** The field was renamed during the refactor from the original codebase but this accessor was missed, and no test exercised the standalone-call deserialization path.

**2. `wrap_rvalue` missing else clause** (`src/genome/codegen.jl:224-228`)
- The if/elseif handled arity 1 and arity 2 functions but had no else branch. For any other arity, the function returned `nothing` implicitly.
- **Impact:** Low in practice (current function sets only have arity 1 and 2), but the `nothing` return would propagate to `ExpansionMutation` where it's caught by the `wrapped !== nothing` guard. Added else clause returning the value unchanged.

**3. Dead `break` after `return`** (`src/genome/codegen.jl:208`)
- Unreachable `break` statement after a `return` in `create_random_assignment`. Cosmetic only; removed.

**4. TreeGenome crossover used `g1.operators` for both offspring** (`src/tree_genome.jl:292`)
- `_subtree_crossover` constructed the second offspring with `g1.operators` and `g1.n_features` instead of `g2`. Harmless in practice (crossover requires same-type parents from the same population), but technically incorrect. Fixed.

**5. `_parse_prefix_expr` and `_tokenize_prefix` rejected SubString** (`src/tree_genome.jl:445,458`)
- Both functions had `s::String` signatures. `deserialize(TreeGenome...)` calls `strip()` which returns `SubString{String}`, causing a MethodError that was silently caught by the try/catch in `_parse_prefix_expr` — every call to `deserialize(TreeGenome...)` returned `nothing`.
- **Impact:** TreeGenome deserialization was completely non-functional. Changed signatures to `AbstractString`.

### Known issues documented but not fixed

- **`_ant_sim_ref` race condition:** Global `Ref{Any}` for ant simulator is not thread-safe with `parallel=true`. Would require per-thread or per-evaluation refactor.
- **TreeGenome serialize/deserialize format mismatch:** `serialize` outputs DynamicExpressions' infix format (e.g., `x1 + 1.0`), but `deserialize` parses prefix format (e.g., `+(x1, 1.0)`). Unary ops round-trip; binary ops do not. This means LLM mutation of TreeGenome would need to produce prefix format.

### Alternatives considered

- **Whether to fix the `_ant_sim_ref` race condition:** Decided not to — it would require either a thread-local storage pattern or passing the simulator through the evaluation pipeline, both of which are significant refactors. The ant genome is primarily a demonstration/benchmark, not a production feature. Documented the limitation instead.
- **Whether to make TreeGenome serialize/deserialize round-trip work:** Would require either changing serialize to output prefix format (breaking DynamicExpressions convention) or adding an infix parser to deserialize (significant complexity). Neither change is warranted right now; documented the mismatch.
