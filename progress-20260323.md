# Progress Log — 2026-03-23

## Phase 3: LLM Operator Extension Complete

### Summary

Implemented the full LLM mutation operator extension for GenProg.jl. The extension provides `LLMMutationOperator`, which implements the FunSearch/AlphaEvolve pattern: serialize genome to source code, prompt an LLM to generate a semantically meaningful variation, parse and validate the response, and fall back to a classical operator on any failure. The extension loads automatically when HTTP.jl is present and does not affect the package when HTTP.jl is absent.

### Key Decisions

1. **No JSON library dependency.** The extension parses LLM API responses (Anthropic and OpenAI formats) using simple regex-based extraction (`_find_last_json_string`) rather than requiring JSON.jl or JSON3.jl. This avoids adding another dependency. The regex approach handles the specific response formats needed and is adequate for extracting a single text field.

2. **`_http_post` Ref{Function} hook for testability.** Instead of monkey-patching HTTP.jl, the extension defines a `const _http_post = Ref{Function}(_default_http_post)` that tests can replace with a mock function. This allows full integration testing without network access or environment variables.

3. **Two provider formats via endpoint detection.** The operator detects Anthropic vs. OpenAI-compatible endpoints by checking if the URL contains "anthropic.com". Anthropic uses the messages API with `x-api-key` header and `anthropic-version`. Everything else uses the OpenAI-compatible format with `Authorization: Bearer` header. This covers Anthropic, OpenAI, and Ollama without code changes.

4. **Silent failure with `@warn`.** All LLM failures (HTTP errors, timeouts, parse failures, type-check failures) log a `@warn` and fall back to `op.fallback_op` (default: `SubtreeMutation()`). The evolutionary loop is never interrupted. This means the GP can run with 0-100% LLM success rate with no behavioral difference beyond mutation quality.

5. **QuoteNode unwrapping in deserialize.** Julia's `repr()` produces `:()` wrapped output (e.g., `":(y = x + 1.0f0)"`). When `Meta.parse` processes this, it returns `Expr(:quote, :(y = x + 1.0f0))`. The deserialize function detects and unwraps these QuoteNodes before type-checking. This makes the round-trip `serialize |> deserialize` work correctly for assignment-only genomes.

6. **Partial recovery in deserialize.** Instead of returning `nothing` on the first invalid line, deserialize skips invalid lines and returns whatever valid assignments survived. This is critical for LLM-generated responses, which may contain explanatory text, comments, or syntactically invalid lines alongside valid code.

7. **HTTP.jl as test extra, not dep.** HTTP.jl remains in `[weakdeps]` for the main package. It's added to `[extras]` and `[targets]` so the test environment has it available, triggering the extension load during `Pkg.test()`.

### Deviations from Specification

1. **Round-trip is partial, not total.** The spec says "The round-trip serialize(g) |> deserialize(ExprGenome, _, g.state) must return a genome with equivalent behavior to g for all valid genomes." In practice, `repr()` can produce forms like `Float32(literal)` that fail strict type-checking because `Float32` is not in the function set as a callable. The round-trip test requires >=80% of genomes to survive (which they do), and surviving genomes have all valid assignments preserved. Assignment-only genomes with simple variable/literal RHS values round-trip perfectly.

2. **LLMMutationOperator not directly in GenProg namespace.** Julia package extensions don't support re-exporting from the parent package. Users access the operator via `Base.get_extension(GenProg, :LLMOperatorExt).LLMMutationOperator`. This is the standard Julia pattern for extension-provided types.
