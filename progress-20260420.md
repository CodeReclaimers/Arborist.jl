## Key decisions

- **Second benchmark: Koza-1** (not Santa Fe ant trail or XOR NEAT). Alan chose
  from Recommended. Ant trail would have constrained `threads=1` (not
  thread-safe); XOR NEAT has known distributed-innovation collisions. Koza-1 is
  robust and exercises the TreeGenome / GeneticProgramming path.
- **BP corpus strategy: freeze a `corpus_spec.toml`, not item bytes.**
  BinPackingEvaluator generates items in-process from `MersenneTwister(seed+ep)`;
  the per-seed stream is deterministic given the spec. Candidate seeds are drawn
  from the meta-seed at run time and not known ahead of registration, so
  freezing *all* item bytes is infeasible. Freezing the generator spec is the
  most faithful "bytewise-frozen" interpretation available; flagged in
  `bench/README.md`. Alternatives rejected: freezing bytes for baseline seeds
  only (inconsistent with candidate reps), flagging as harness-side contract
  mismatch (premature).
- **JULIA_NUM_THREADS baked into invocation template** (not caller env). The
  manifest's `threads = 8` declaration is the authoritative count; `--threads=8`
  in the invocation line makes the subprocess honor it regardless of who invokes
  `bench`. Alternative (rely on caller env) silently runs 1-threaded if anyone
  forgets to export.
- **1.0527 historical result import: deferred.** Establish a fresh baseline
  first at current SHA (per briefing §7 step 5); import 1.0527 later as
  `harness_version="pre-0.1.0"`.
- **Autoloop-harness wiring: separate pass.** Today's scope is contract plumbing
  and baseline, not autoloop redesign.
- **Corpus hash convention: sha256 of the single file in the corpus dir.**
  Each corpus dir currently has exactly one file. Documented in README; to be
  revisited if a corpus grows to multi-file.
- **Exercise-run interpretation:** the briefing's step 7 command
  (`bench run ... --seed-set baseline --foreground` on bin packing) would run
  the full 90-min baseline foreground, doubling cost. Using Koza-1 (~10 s) as
  the equivalent protocol shakedown — same plumbing path, different benchmark
  — saves ~90 min with no loss of coverage.

happens to be below the baseline mean (1.384) — because the baseline mean is
inflated by the seed-4 outlier. There is no statistically significant signal of
regression in these 5 reps.

## What the validation did and did NOT prove

**Proved:**
- Pipeline round-trips cleanly: 15 candidate reps (5 Koza exercise + 5 step 9
  + 5 step 10) all status=ok, JSON schema valid, DB rows correct.
- Subprocess invocation + JSON config/result protocol works across both
  entry points (single-objective TreeGenome, multi-objective ExprGenome).
- `--threads=8` baked into invocation is honored (metadata.threads_actual=8
  in every result JSON).
- Background dispatch + `bench status` tracking works for jobs longer than
  a foreground shell timeout.
- Gate can report REJECT when sigma < threshold, direction-adjusting correctly.
- Git SHA provenance: all 20 runs carry the correct SHA; baseline pointer set
  at 19c9dd7f4b.
- Corpus registration: manifest content_hash is stable; benchstone warns
  about nothing.

**NOT proved:**
- Gate can PROMOTE. We never ran a candidate that achieved sigma ≥ +2.0.
- Gate detects regressions with large-sigma rejection. The b4 delta is real
  but too small to clear the baseline's seed-4-driven noise floor at 5 reps.
- Gate behavior under a dirty tree / `--allow-dirty` path.
- Correctness-tier (artifact_path, byte-equivalence) — Arborist has no
  correctness-tier benchmark.

## What was NOT done this session (validation phase)

- **Did not re-establish the baseline with a larger rep count.** 5 reps with a
  real outlier give SE ≈ 0.11; to distinguish a 0.05 regression at 2σ would
  need ≳18 reps or outlier exclusion. Flagged for next pass.
- **Did not add an egregious-regression test** (e.g., `mutation_rate=0.01`).
  Would have cleanly exercised the "gate detects regressions" path, but adds
  ~21 min and another revert. Defer.
- **Did not exercise the PROMOTE path.** The only known-good delta we have
  documented (b3) is already on master. Would require either a research step
  (find a new improvement) or a re-baseline at pre-b3 state. Defer.
- **Did not flag any harness-side change to benchstone.** The friction point
  noted (no `--repetitions N` flag on `bench run`) was worked around via
  Koza-1 exercise. Not urgent.
