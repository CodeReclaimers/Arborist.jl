### Session 2: timing probe

Timed a classical NSGA-II bin packing run with 32 threads to size the
4-hour autoloop budget:

- **init + 1 gen**: 123.7 s (dominated by the 10k-genome behavioral-init
  pool evaluation).
- **init + 10 gens**: 132.7 s.
- **Per-generation slope**: ~1.0 s/gen after init.
- **Extrapolation**: 3 seeds × 200 gen ≈ 16 min per trial with the full
  10k pool. With autoloop's ~3 min/trial subagent overhead, that gives
  ~12 experiments in 4 hours — tight.

Key finding: init dominates runtime. Reducing the screen-metric pool
from 10k to 2k recovers ~100 s per seed × 3 seeds = ~5 min per trial,
roughly doubling the trial budget.

### Session 3: editable surface + metric harness

Created two new files to keep the autoloop's target glob narrow and
prevent metric gaming:

- **`examples/nsga2_tuning_config.jl`** (new, editable surface). A
  single `build_tuning_algorithm(; generations)` function that returns
  an `NSGAII` algorithm plus `num_temps`. This is the ONLY file the
  autoloop subagent is allowed to edit. Allowed knobs: `pop_size`
  (even, ≥4), `mutation_rate`, `crossover_rate`, `mutation_ops`,
  `crossover_ops`, `num_temps`.
- **`examples/nsga2_tuning_metric.jl`** (new, off-limits to subagent).
  Metric harness: compiles the candidate NSGAII, runs three training
  seeds (42, 123, 1337), evaluates each run's lowest-fitness Pareto
  member on test seed `train + 1000`, prints mean test fitness as the
  single scalar on the last non-empty line of stdout. Honors
  `BP_POOL_SIZE` env var and a `--holdout` flag.

### Session 4: `BP_POOL_SIZE` plumbing

### Key decisions

- **Narrow editable surface**: chose option (a) — a separate
  `nsga2_tuning_config.jl` — over (b) wide glob on `bin_packing.jl`
  with prose restrictions or (c) rely on holdout regression to catch
  metric gaming. Rationale: `autoloop`'s `target_glob` is file-level.
  Keeping the evaluator and test harness out of the glob mechanically
  prevents the subagent from editing them even on a bad turn, which
  is stronger than hoping the holdout catches it.
- **Env-var pool plumbing over kwargs**: chose `BP_POOL_SIZE` env var
  over threading `pool_size` through function signatures. Reason: the
  env var keeps the edit footprint to two identical 1-line changes and
  does not require the metric runner to touch the config file's API.
- **Metric = mean test fitness across 3 seeds**: not hypervolume, not
  Pareto-front size. Reason: test fitness matches the published
  "1.0527" benchmark that we want to beat; hypervolume is scale-sensitive
  and incomparable across operator-set changes.
- **Screen-metric pool 2k, holdout pool 10k**: smaller behavioral
  init speeds up per-trial cost without compromising the full-scale
  validation of any candidate the loop promotes.
