### Findings (ranked by impact)

1. **GraphGenome non-deterministic Dict iteration (6 sites)** — `_mutate_weights!`, `_mutate_weight_replace!`, `_mutate_add_connection!`, `_mutate_add_node!`, `_mutate_toggle_connection!`, and `_neat_crossover` all iterate Dict values/keys/Sets with RNG consumption in non-deterministic order. Directly violates the documented convention "Collection sampling uses deterministic sorted ordering." GraphGenome evolution is NOT reproducible from a fixed seed across Julia sessions. `_topological_sort` and `evaluate_genome` are correctly deterministic.

2. **GraphGenome crossover produces identical children for disjoint parents** — `crossover(g1, g2, rng)` calls `_neat_crossover(fitter, other, rng)` twice with the same parent order. When parents share no innovation numbers, both children are identical copies of the fitter parent. The less-fit parent's unique structural innovations are systematically excluded from both children. Standard NEAT produces one child; the framework needs two — swapping parent order for the second child would preserve more genetic material.

3. **Missing operator rate validation** — `GeneticProgramming` constructor does not check `crossover_rate + mutation_rate <= 1.0`. When sum exceeds 1.0, effective mutation rate becomes `1.0 - crossover_rate` (silently clamped) and reproduction is eliminated. Legacy `evolve!` has the same pattern. No existing tests cover this edge case.

4. **`GeneticProgramming.max_depth` is dead code** — Declared in the struct, accepted by the constructor, never read by any code in `src/`. Users setting `max_depth` expecting depth-limited trees are silently ignored.

5. **Migrant ExprGenome RNG contamination** — When ExprGenome migrates between islands, `deepcopy` copies the source island's GenState (including RNG). Mutations on the destination island use dual RNG streams: destination's for node selection, source's for content generation. Determinism is preserved (deepcopy is deterministic) but the explicit-RNG-everywhere convention is violated architecturally.

6. **NEAT distance 2x scaling** — Formula uses `(c1+c2)*(E+D)/N` instead of standard NEAT `c1*E/N + c2*D/N`. With defaults c1=c2=1.0, structural distance is 2x standard. Internally consistent but speciation thresholds don't match NEAT literature values. Documentation gap.

7. **LLM operator missing try/catch around deserialize/sanitize** — Lines 181 and 189 of `llm_operator.jl` are not wrapped in try/catch. `deserialize` internals are effectively safe (all sub-calls have their own try/catch), but `StackOverflowError` from deeply nested LLM output could theoretically crash the loop. Trivial fix: one try/catch block.

8. **JSON unescape order bug** — `_find_last_json_string` unescapes `\\\\` after `\\n`/`\\t`/`\\"`. Correct order is `\\\\` first to avoid double-unescaping of literal backslash sequences. Negligible practical impact for LLM-generated Julia code.

### Key Decisions

- **Scope limited to finding, not fixing.** RESEARCH.md specified "Do NOT investigate autonomously: Fixes for any discovered bugs" and "Do NOT change without human approval: Any files already in the project." All findings are documented for human review.
- **Iteration 001 focused on boundaries.** The protocol prioritizes component interactions over isolated correctness. The RNG contamination finding (migrant GenState carrying foreign RNG into mutations) came from examining the boundary between island migration and mutation operators.
- **Classified Gemini's "recurrent NEAT" finding as known.** The code deliberately uses topological sort (feedforward NEAT only). The paper doesn't claim recurrent network support.
- **Refuted Gemini's challenge to fitness sharing claim.** Gemini argued the paper's description of `:linear` sharing inverting selection was misleading. The paper is correct: with minimization (lower=better), `shared = raw * species_size` causes a singleton at raw fitness 2.0 to beat a species-5 member at raw fitness 1.10 (shared 5.5) because 2.0 < 5.5.
