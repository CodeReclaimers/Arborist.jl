## Review items and dispositions

### Blocking items (reviewer's categorization)

1. **`Project.toml` missing `license` field.** Valid with nuance —
   the Julia General registry does not actually *require* this key
   (it requires a `LICENSE` file, which the repo has), but several
   tooling paths read it and adding it is free. Added
   `license = "MIT"` to match the existing MIT `LICENSE` file.

2. **`IslandModel` only supports `ExprGenome`.** Valid. Confirmed
   via `src/solve.jl:34-37` that `_initialize_population` explicitly
   errors for any `G !== ExprGenome`, and both the sequential path
   (`solve.jl:292`) and the distributed path
   (`distributed_island.jl:51`) go through that function. `TreeGenome`,
   `AntGenome`, and `GraphGenome` each provide their own top-level
   `solve(::GPProblem, ::GeneticProgramming)` methods but no
   `IslandModel` dispatch. Fixed by narrowing the public claims
   (README + docs) rather than implementing the missing dispatch.

   **Rejected alternative:** adding `IslandModel` support for the
   three other genome types. This is real feature work — each
   genome has its own population construction signature (`GenState`,
   `OperatorEnum + n_features`, primitives, input/output counts) and
   the distributed backend would need `GraphGenome` innovation-counter
   coordination — and is not a pre-registration fix. Deferred to a
   future release.

3. **`AbstractGenome` interface docstring mismatch.** Valid. The
   docstring claimed every subtype must implement
   `initialize(::Type{G}, problem::GPProblem)` and
   `deserialize(::Type{G}, s::String)`, but none of the four genome
   types match those exact 2-arg signatures:
   - `ExprGenome.initialize` matches but `deserialize` requires a
     `GenState` positional arg (`expr_genome.jl:139`); a keyword-arg
     compatibility shim exists at `expr_genome.jl:164` but returns
     `nothing` when `state === nothing`, which is not a useful
     implementation of the documented contract.
   - `TreeGenome.deserialize` requires `(operators::OperatorEnum, n_features::Int)`.
   - `AntGenome.initialize` takes `(primitives::Vector{Symbol}, …)`.
   - `GraphGenome.initialize` takes `(n_inputs, n_outputs, …)`.

   Rewrote the docstring to describe the actual contract: per-genome
   construction and deserialization signatures that the matching
   `solve` paths invoke directly. The new docstring also clarifies
   that `LLMMutationOperator` currently only dispatches on
   `ExprGenome`, so the `deserialize` extension is only load-bearing
   for that one type.

   **Rejected alternative:** adding 2-arg `initialize`/`deserialize`
   methods to every genome to match the old docstring. This would
   have required threading a `problem::GPProblem` through
   construction paths that do not currently need it, and would have
   produced partial methods for `deserialize` (`TreeGenome` genuinely
   needs the operator enum). Changing docs to match code is the
   correct direction.

4. **`NSGAII` only supports `ExprGenome` + `TreeGenome`.** Valid.
   `nsga2.jl:462` declares `_nsga2_init_population` and only provides
   methods for those two genome types. Fixed by documentation
   (README + `docs/src/algorithms.md`). Expanding NSGA-II to
   `AntGenome` and `GraphGenome` deferred alongside item 2.

### Non-blocking items

5. **Directory name `GenProg.jl` vs package `Arborist`.** Out of
   scope for a code fix; would require repository rename. Not

6. **`Manifest.toml` in root.** Reviewer was mistaken. Confirmed

7. **`src/genome/linear_genome.jl` empty placeholder.** Already
   staged for deletion (visible as `D src/genome/linear_genome.jl`

8. **Distributed NEAT innovation counter collision.** Valid. The
   limitation was documented in `CLAUDE.md` and as a comment in

   Added a `!!! warning` block to `docs/src/reproducibility.md`

## Session 3 — IslandModel + TreeGenome support

### Summary

Extended `IslandModel` to dispatch on `TreeGenome` in addition to
`ExprGenome`. All three execution modes — sequential, synchronous
distributed, and asynchronous distributed — now work end-to-end with
`TreeFitnessEvaluator`-backed symbolic regression problems. This
closes the only practically important gap in the 0.1.0 IslandModel
genome coverage: `TreeGenome` is ~8× faster per evaluation than
`ExprGenome` and is the canonical pick for symbolic regression, so
users wanting to scale symbolic regression across workers were
previously forced into the single-population `solve` path.

`AntGenome` and `GraphGenome` remain unsupported — both are blocked
upstream (module-level `Ref` in the ant simulator, process-local
NEAT innovation counter in GraphGenome) and neither was requested.

### Files Modified

- **`src/tree_genome.jl`** — added:
  - `TreeGenomeContext{T}` struct with `rng::AbstractRNG`,
    `operators::OperatorEnum`, `n_features::Int`. The field name
    `rng` deliberately matches `GenState.rng` so the existing
    `state.rng` accesses in the IslandModel sequential loop
    (`src/solve.jl:328, :346`) compile unchanged under a widened
    container type.
  - `_initialize_population(::GPProblem{TreeGenome{T},E}, alg, rng)`
    method. Requires the evaluator to be a `TreeFitnessEvaluator`
    (no `ParsimonyEvaluator` unwrap — `IslandModel` is
    single-objective only; NSGA-II is a separate dispatch), extracts
    `operators` and `n_features` from the evaluator, fills a ramped
    half-and-half population via `_random_tree` with depths 2–4.
    Returns `(genomes, TreeGenomeContext{T}(rng, ops, n_feat))`.
  - `to_migrant(::TreeGenome{T}, ::Float64)` / 
    `from_migrant(::MigrantGenome, ::TreeGenomeContext{T})` — packs
    the `Node{T}` directly into `MigrantGenome.data` rather than
    going through `serialize`/`deserialize`.

- **`src/solve.jl`** — split `_initialize_population` into an
  explicit `GPProblem{ExprGenome,E}` method plus a generic fallback
  that errors with an updated message ("supports ExprGenome and
  TreeGenome; other genome types require a specialized solve
  method"). In the sequential `IslandModel` path, widened
  `island_states::Vector{GenState}` to `Vector{Any}` at line 285 so
  per-island state can hold either `GenState` (ExprGenome) or

- **`src/distributed_island.jl`** — widened `IslandState{G}.state`

- **`test/integration/test_island_tree_genome.jl`** (new, 5

- **`README.md`** — updated the one-sentence IslandModel feature

  `AntGenome` and `GraphGenome` use their own single-population
  `solve` paths."

### Key Decisions

- **Migration transports `Node{T}` directly, not `serialize`
  output.** The first draft routed `to_migrant`/`from_migrant`
  through the existing string-based `serialize`/`deserialize` pair
  (`src/tree_genome.jl:171-180`). The sequential smoke test passed
  because the sequential `_migrate!` in `src/solve.jl` uses
  `deepcopy` and never touches `to_migrant`. The sync-distributed
  smoke test then failed on the first migration event with
  `Failed to deserialize TreeGenome migrant: abs(0.73232263 * (x1 + x1)) + x1`.

  **Root cause:** `serialize(::TreeGenome)` produces **infix**
  notation via DynamicExpressions' `string_tree`, but
  `deserialize(::Type{TreeGenome{T}}, s, ops, n_features)` parses
  **prefix** notation. Binary operators do not round-trip — this
  is a pre-existing known limitation already documented in
  `CLAUDE.md` ("TreeGenome serialize/deserialize format mismatch:
  serialize outputs infix (x1 + 1.0), deserialize parses prefix
  (+(x1, 1.0))").

  **Fix:** pack `Node{T}` directly into `MigrantGenome.data`
  (typed `::Any`). Julia's Distributed serializer handles
  `Node{T}` natively across process boundaries. Op indices stored
  in each node are stable across islands because every island
  holds the same `OperatorEnum` constructed once from the problem,
  so no index remapping is required on the receiving end.

  **Rejected alternative:** fix the TreeGenome serialize/deserialize
  format mismatch in this session. That is a real bug and should
  eventually be fixed (it also cripples LLM mutation of
  TreeGenome), but it is out of scope for this feature work. The
  `Node{T}`-direct approach is strictly better for migration
  anyway — no parse ambiguity, no round-trip through strings,
  exact bit-for-bit tree preservation.

- **`TreeGenomeContext` instead of a new abstract type or a
  dispatch helper.** Three alternatives were considered:
  1. A small abstract `IslandContext` type with `GenState` and
     `TreeGenomeContext` as subtypes. Rejected: adds a type layer
     for two concrete cases and forces every file that mentions
     the context to import a new abstract type.
  2. A `_state_rng(x)` helper dispatching `GenState → x.rng`,
     `AbstractRNG → x`, plus returning just the `rng` from
     `_initialize_population`. Rejected: would have required
     rewriting every `state.rng` callsite and still needed a
     separate context object on the distributed path for
     `_inject_migrants_local!` to reconstruct `TreeGenome`s.
  3. A concrete struct with the field name `rng` matching
     `GenState.rng`. Chosen — the existing `state.rng` reads at
     `src/solve.jl:328` and `:346` compile unchanged when the
     container is widened to `Vector{Any}`, and
     `from_migrant(m, island.state)` dispatches on the runtime
     type without needing a helper.

- **`Vector{Any}` instead of `Vector{Union{GenState, TreeGenomeContext}}`.**
  The typed Union preserves a bit more static type information but
  ripples through every `IslandState{G}` annotation in
  `distributed_island.jl` and couples the IslandModel machinery to
  the specific set of supported context types. `Any` keeps the
  machinery open to future context types without further edits.
  The hot loop never reads the field directly — only `state.rng` —
  so type instability costs nothing measurable. Can be revisited
  if a future profile shows the access matters.

- **Tests use `Random.MersenneTwister(0)` for the `TreeGenomeContext`
  in the round-trip test.** The round-trip doesn't actually consume
  RNG state — the reconstructed `TreeGenome` only needs `operators`
  and `n_features` from the context — but the context constructor
  takes an RNG positionally, so an explicit zero-seeded RNG is the
  cleanest way to write the test without a dummy RNG helper.

## Session 2 — TreeGenome serialize/deserialize round-trip fix

### Summary

Implemented `plan_treegenome_parser_fix.md`. Replaced the hand-rolled
prefix-only tokenizer in `src/tree_genome.jl` with a single
`Meta.parse`-based walker that handles both DynamicExpressions' infix
output (`x1 + 1.0`, what `serialize` emits) and the prefix
s-expression form (`+(x1, 1.0)`) used by the prior parser. Net effect:
`serialize → deserialize` is now a true round-trip for any tree
DynamicExpressions can evaluate. The "TreeGenome serialize/deserialize
format mismatch" entry was removed from `CLAUDE.md` Known Limitations,
and the `to_migrant` docstring was updated to drop its reference to
that now-removed entry (the rationale — no parse ambiguity, exact
bit preservation, format independence — is stated directly).

### Files modified

- `src/tree_genome.jl`
  - `deserialize(::Type{TreeGenome{T}}, ...)`: signature widened from
    `s::String` to `s::AbstractString`. Now strips, calls `Meta.parse`
    in a try/catch, and dispatches through `_expr_to_node`. The catch
    block follows the project pattern
    `catch e; e isa InterruptException && rethrow(); return nothing`.
    Added a docstring describing dual-form acceptance.
  - Replaced `_parse_prefix_expr` / `_tokenize_prefix` /
    `_parse_prefix_token` (~125 lines, formerly at 521-646) with a
    single `_expr_to_node` walker (~50 lines). Walker accepts numeric
    literals (any `Number` widened to `T`), feature symbols matching
    `^x(\d+)$`, and `Expr(:call, op, args...)` of arity 1 (unary) or
    2 (binary). Operator lookup preserves the dual-symbol match
    pattern `Symbol(op) == sym || Symbol(nameof(op)) == sym`.
  - `to_migrant(::TreeGenome)` docstring rewritten to drop the stale
    "see CLAUDE.md known limitations" reference.

- `test/integration/test_tree_genome.jl`
  - Updated the comment block at the head of the
    `"TreeGenome serialize/deserialize round-trip"` testset (formerly
    documented the bug; now describes the dual-form acceptance).
  - Existing prefix-form tests at lines 107-134 left unchanged as the
    backward-compatibility regression guard.
  - Folded new round-trip tests into the same testset: single
    terminal, the historical `x1 + 1.0` failure case, all four binary
    ops in isolation, all three unary ops in isolation, nested
    `sin((x1 + 1) * x1)`, and 10 `_random_tree` instances seeded with
    `MersenneTwister(42)`.

- `CLAUDE.md`
  - Removed the "TreeGenome serialize/deserialize format mismatch"

  - Refreshed test counts in Project Status: fast tier
    `3065 → 3164` / `~51s → ~1m08s`; full benchmarks

- `plan_treegenome_parser_fix.md` — the plan being implemented (was

### Key decision: `isequal` vs `==` in the round-trip predicate

The plan said "use `==`, not `≈`, because the reconstructed tree is
bit-identical." Initial test run failed on 2/10 random trees from the
seed-42 generator. Diagnosis: the trees were bit-identical (verified
by comparing `reinterpret(UInt32, p1) .== reinterpret(UInt32, p2)`,
which returned `all true`), but the input matrix
`reshape(Float32.(range(-2, 2, length=25)), 1, :)` contains `0`
exactly, and several random trees evaluated `1.9527.../x1` →
`Inf`/`NaN` at that point. Julia's `==` returns `false` for `NaN ==
NaN`; `isequal` returns `true`. Switched to `isequal(p1, p2)` to
match the plan's stated "bit-identical" intent rather than working
around the input matrix or filtering NaN. Documented inline.

**Rejected alternatives:**
- Choose an `X` that avoids `0` (e.g. `range(-2, 2, length=24)` or
  shifting by `0.01`). Rejected: changes the test to dodge a
  legitimate semantic issue rather than expressing what we actually
  want to assert (bit equality including NaN).
- Filter NaN/Inf elementwise. Rejected: more code, same result, and
  loses the assertion that NaN positions match.
