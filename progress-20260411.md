# 2026-04-11 — Pre-registration review fixes

## Summary

Reviewed an external code review of Arborist.jl against the actual
source before acting. Three of the reviewer's "blocking" items were
valid (with nuance), one was already fixed in the working tree, and
one of the "non-blocking" items was based on a misread of the repo
state. Applied targeted fixes to the valid items; deferred the two
that would require real feature work (extending `IslandModel` and
`NSGAII` to all genome types) to post-0.1.0.

## Files modified

- `Project.toml` — added `license = "MIT"`.
- `src/abstractions.jl` — rewrote the `AbstractGenome` docstring.
- `README.md` — narrowed the `NSGAII` and `IslandModel` feature
  descriptions to state which genomes they actually dispatch on.
- `docs/src/algorithms.md` — added `!!! note` admonitions under the
  `IslandModel` and `NSGAII` sections with the same genome-support
  caveats, plus a pointer that unsupported genomes raise `MethodError`
  from `_nsga2_init_population`.
- `docs/src/reproducibility.md` — added a `!!! warning` under
  "GraphGenome Reproducibility" about the per-process innovation
  counter silently corrupting NEAT topologies under distributed
  islands.

## Review items and dispositions

### Blocking items (reviewer's categorization)

1. **`Project.toml` missing `license` field.** Valid with nuance —
   the Julia General registry does not actually *require* this key
   (it requires a `LICENSE` file, which the repo has), but several
   tooling paths read it and adding it is free. Added
   `license = "MIT"` to match the existing MIT `LICENSE` file.

2. **`IslandModel` only supports `ExprGenome`.** Valid. Confirmed
   via `src/solve.jl:34-37` that `_initialize_population` explicitly
   errors for any `G !== ExprGenome`, and both the sequential path
   (`solve.jl:292`) and the distributed path
   (`distributed_island.jl:51`) go through that function. `TreeGenome`,
   `AntGenome`, and `GraphGenome` each provide their own top-level
   `solve(::GPProblem, ::GeneticProgramming)` methods but no
   `IslandModel` dispatch. Fixed by narrowing the public claims
   (README + docs) rather than implementing the missing dispatch.

   **Rejected alternative:** adding `IslandModel` support for the
   three other genome types. This is real feature work — each
   genome has its own population construction signature (`GenState`,
   `OperatorEnum + n_features`, primitives, input/output counts) and
   the distributed backend would need `GraphGenome` innovation-counter
   coordination — and is not a pre-registration fix. Deferred to a
   future release.

3. **`AbstractGenome` interface docstring mismatch.** Valid. The
   docstring claimed every subtype must implement
   `initialize(::Type{G}, problem::GPProblem)` and
   `deserialize(::Type{G}, s::String)`, but none of the four genome
   types match those exact 2-arg signatures:
   - `ExprGenome.initialize` matches but `deserialize` requires a
     `GenState` positional arg (`expr_genome.jl:139`); a keyword-arg
     compatibility shim exists at `expr_genome.jl:164` but returns
     `nothing` when `state === nothing`, which is not a useful
     implementation of the documented contract.
   - `TreeGenome.deserialize` requires `(operators::OperatorEnum, n_features::Int)`.
   - `AntGenome.initialize` takes `(primitives::Vector{Symbol}, …)`.
   - `GraphGenome.initialize` takes `(n_inputs, n_outputs, …)`.

   Rewrote the docstring to describe the actual contract: per-genome
   construction and deserialization signatures that the matching
   `solve` paths invoke directly. The new docstring also clarifies
   that `LLMMutationOperator` currently only dispatches on
   `ExprGenome`, so the `deserialize` extension is only load-bearing
   for that one type.

   **Rejected alternative:** adding 2-arg `initialize`/`deserialize`
   methods to every genome to match the old docstring. This would
   have required threading a `problem::GPProblem` through
   construction paths that do not currently need it, and would have
   produced partial methods for `deserialize` (`TreeGenome` genuinely
   needs the operator enum). Changing docs to match code is the
   correct direction.

4. **`NSGAII` only supports `ExprGenome` + `TreeGenome`.** Valid.
   `nsga2.jl:462` declares `_nsga2_init_population` and only provides
   methods for those two genome types. Fixed by documentation
   (README + `docs/src/algorithms.md`). Expanding NSGA-II to
   `AntGenome` and `GraphGenome` deferred alongside item 2.

### Non-blocking items

5. **Directory name `GenProg.jl` vs package `Arborist`.** Out of
   scope for a code fix; would require repository rename. Not
   addressed this session.

6. **`Manifest.toml` in root.** Reviewer was mistaken. Confirmed
   via `git ls-files Manifest.toml` (empty output) that the file is
   not tracked, and `.gitignore` already contains `Manifest.toml`
   and `docs/Manifest.toml`. The file present in the working tree
   is a local artifact only. No action needed.

7. **`src/genome/linear_genome.jl` empty placeholder.** Already
   staged for deletion (visible as `D src/genome/linear_genome.jl`
   in `git status` at session start). No action needed.

8. **Distributed NEAT innovation counter collision.** Valid. The
   limitation was documented in `CLAUDE.md` and as a comment in
   `src/distributed_island.jl` but not in the user-facing docs.
   Added a `!!! warning` block to `docs/src/reproducibility.md`
   explaining that the innovation counter is process-local, why
   that breaks NEAT crossover under distributed islands, and that
   the concern is currently latent because `IslandModel` is itself
   `ExprGenome`-only.

### Unverifiable claims (reviewer's categorization)

9, 10. TreeGenome 8.4× speedup and Koza 5/5 convergence. Not
re-verified this session — these come from benchmark runs already
captured in earlier progress logs. No action needed.
