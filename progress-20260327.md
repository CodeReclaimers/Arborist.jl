# Progress Log — 2026-03-27

## Lorenz attractor recovery benchmark

### Summary

Implemented the Lorenz attractor recovery benchmark from §9 of the original design plan. This is a symbolic regression problem on a chaotic dynamical system — given trajectory data from the Lorenz equations, recover the derivative expressions from numerical data alone. Uses TreeGenome (DynamicExpressions.jl) for fast vectorized evaluation.

### Data generation

- **RK4 integration** (4th-order Runge-Kutta) at dt=0.005, 2000 steps from (1,1,1)
- Standard Lorenz parameters: σ=10, ρ=28, β=8/3
- Central-difference numerical derivatives, subsampled to 100 training points
- **Normalized derivatives** — divided by standard deviation so MSE of predicting zero ≈ 1.0, making fitness thresholds interpretable regardless of trajectory parameters

### Three sub-benchmarks

| Component | True expression | Difficulty | Convergence (< 0.1) | Best fitness | Assertion |
|-----------|----------------|------------|---------------------|--------------|-----------|
| dx/dt | σ(y - x) = 10y - 10x | Linear combination | 4/5 seeds | 0.0 | ≥3/5 |
| dy/dt | x(ρ - z) - y = 28x - xz - y | Cross-term xz | 2/5 seeds | 0.0743 | ≥2/5 |
| dz/dt | xy - βz = xy - 2.667z | Cross-term xy | 2/5 seeds | 0.0006 | ≥2/5 |

### Design decisions

**RK4 instead of forward Euler.** Original implementation used Euler at dt=0.001. Alan requested RK4 at dt=0.005 — 5x fewer steps for the same trajectory length with O(h⁴) accuracy vs O(h). The larger time step covers 10 time units of trajectory (vs 2 with Euler), giving more dynamic range in the training data.

**Normalized derivatives.** With the longer RK4 trajectory, raw derivative variance was 745–2698. An MSE threshold of 1.0 would be trivially easy (just predict the mean). Normalizing by std makes fitness < 0.1 mean "explains >90% of variance" — a meaningful threshold that's consistent with the Koza benchmarks.

**Tiered convergence requirements.** dx/dt (linear) requires ≥3/5 seeds at fitness < 0.1. The cross-term components (dy/dt, dz/dt) require ≥2/5 — these are genuinely harder because the function set must discover multiplicative cross-terms (xz, xy) from {+, -, *, /, abs}.

**Inline `_std` helper.** Statistics.jl is a stdlib but wasn't in the test environment's Project.toml. Rather than adding a dependency for one function, computed std inline.

## Lorenz recovery example + TreeGenome promoted to core

### Lorenz example

Created `examples/lorenz_recovery.jl` — a standalone, stripped-down version of the Lorenz benchmark intended as a code example. Uses Euler integration (simpler than the RK4 benchmark) for data generation. Shows:
- The true Lorenz equations alongside the GP-discovered expressions
- Fit statistics per component: MSE, RMSE, R-squared, max error, node count
- Expression truncation for readability (cap at 200 chars)
- Bloat penalty (0.005) to encourage simpler expressions
- CLI args: `--seed`, `--generations`, `--pop_size`

Typical output with 500 generations: dx/dt R²=0.9999, dz/dt R²=0.999, dy/dt R²=0.94 (hardest cross-term).

### DynamicExpressions promoted from weakdep to direct dependency

TreeGenome is a first-class genome type used by all symbolic regression benchmarks (Koza, Lorenz, boolean parity, speedup). Keeping it as a weakdep/extension required users to `Pkg.add("DynamicExpressions")` separately and use the awkward `Base.get_extension` pattern.

**Change:** Moved `ext/DynExprExt.jl` → `src/tree_genome.jl`. Removed the `module DynExprExt` wrapper, `using Arborist` imports, and `Arborist.` method prefixes. Added `include("tree_genome.jl")` in `src/Arborist.jl`. Exported `TreeGenome`, `TreeFitnessEvaluator`, `SymbolicRegressionEvaluator` directly from Arborist.

Also during the move:
- Replaced the duplicated breeding loop with `_breed_next_generation!` (the 6th instance — missed during the earlier refactor because it was in `ext/`)
- Fixed stale `algorithm.tournament_size` reference (used the removed struct field)

**Dependency cost:** 9 external packages total (DynamicExpressions + ChainRulesCore, Compat, DispatchDoctor, Interfaces, MacroTools, PrecompileTools, Preferences, Reexport). All lightweight metadata/utility packages. Significantly lighter than the 14 packages HTTP.jl imposed.
