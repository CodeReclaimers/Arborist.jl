### Key Decisions

1. **Explicit RNG threading (deviation from "verbatim" copy):** The user explicitly instructed that all stochastic operations must accept and use an explicit `rng::AbstractRNG` parameter instead of relying on global `rand()`/`randn()`. This required modifying codegen.jl and evolution.jl — adding an `rng` field to `GenState` and replacing every `rand()`/`randn()` call with `rand(s.rng, ...)`/`randn(s.rng, ...)`. The alternative (global RNG seeding) was rejected because it makes the GP non-reproducible when embedded in larger applications.

2. **Deterministic collection ordering:** Julia's `Dict` and `Set` iteration order depends on hash values that can differ between processes (due to `objectid`-based hashing of DataType). This caused the GP to produce different results across `Pkg.test()` invocations even with the same RNG seed. Fixed by sorting all collections into canonical order before sampling: `_sorted_pairs(dict)` sorts by key, `_sorted_funcs(set)` sorts FunctionDetails by name/type/arity, `_sorted_types(set)` sorts DataTypes by string representation.

3. **Deterministic temp variable names:** Replaced `gensym()` with `Symbol("__temp_$i")` for temp variable names in the GenState constructor. `gensym()` uses a global counter whose state differs between sessions, which changes Dict key hash values and therefore iteration order. Fixed names ensure reproducibility.

4. **Generous time limit in benchmarks:** Set `time_limit_ns=1_000_000_000` (1 second) instead of 10ms in benchmark tests. The tight time limit created non-determinism because GC pauses and JIT compilation timing vary between runs, causing some evaluations to randomly exceed the limit and receive fitness=Inf. Loop safety is provided by `add_loop_checks` with `LoopLimitExceeded` exceptions instead.

5. **FitnessEvaluator as const alias:** Instead of duplicating the abstract type, defined `const FitnessEvaluator = AbstractEvaluator` so that existing code referencing `FitnessEvaluator` (in Population, evaluate_individual!, etc.) works with the new type hierarchy.

6. **No README.md/LICENSE/docs:** System instructions prohibit creating documentation files unless explicitly requested. The plan's Section 8 file layout includes these, but they were omitted. This is a known deviation.

### Key Decisions

1. **ThresholdSpeciation integration point:** Speciation runs after evaluation and sorting, before selection. The function returns `selection_fitnesses` (fitness-shared values) used for tournament selection, while `fitnesses` (raw + bloat penalty) is used for history recording and elitism. This separation ensures the history tracks actual performance, not shared fitness.

2. **Species state persistence:** `_SpeciesInfo` tracks representative genome, best fitness, and stagnation counter across generations. Species representatives are updated to the best individual each generation. Stagnation increments when improvement is < 1e-6.

3. **Culling criteria:** A species is culled only when BOTH conditions are met: stagnation > stagnation_limit AND species size < min_species_size. The global best individual's species is never culled. Orphaned individuals from culled species are redistributed to the nearest remaining species by distance.

4. **IslandModel: sequential execution:** Islands run one generation at a time in sequence, not in parallel. This avoids threading complexity and is sufficient for correctness testing. Parallelism is Phase 5+ work.

5. **IslandModel: ring migration:** Every `migration_interval` generations, the top `migration_size` individuals from each island are deepcopy'd to the next island (ring topology). They replace the worst individuals on the receiving island. Migrated individuals get fitness=Inf and are re-evaluated on the next generation.

6. **Boolean parity: 2-bit instead of 4-bit.** The ExprGenome system with @eval compilation is too slow for 4-bit parity — each seed takes 11+ minutes because the evolved boolean programs generate complex nested structures (loops, blocks) that are expensive to compile via @eval. 2-bit parity (essentially XOR) verifies boolean GP capability in practical test time (~50s per seed). This is a deviation from the spec which called for 4-bit parity.

7. **Benchmark seed count: 5 instead of 10.** Each Koza benchmark seed takes ~2 minutes due to @eval overhead. With 10 seeds × 3 benchmarks, the Koza suite alone would take ~60 minutes. Using 5 seeds with 3/5 threshold provides practical test times (~30 min for all Koza benchmarks) while still verifying majority convergence.

8. **gp_nand and gp_nor in GenProg module.** Boolean NAND and NOR operators are defined in the GenProg module (not Base) because @eval'd evolved code resolves names in module scope. These are exported and available to users building boolean function sets.
