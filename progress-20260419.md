### Key decisions

- **Option (c) chosen for metric pool**: use the full 10k behavioral-init
  pool for both screen and holdout rather than split (2k screen + 10k
  holdout). Rationale: the 2k-pool baseline gave mean test 1.5006 —
  1.50 is too far from the Best Fit regime (1.09) for candidate
  rankings to reliably transfer. Cost: fewer total trials per 4h budget
  (~6 instead of ~12). Benefit: cleaner signal.
- **2σ = 0.02 promotion threshold**, switched down from 3σ at user
  direction after seeing the canonical config (1.2641) was already near
  Best Fit. 3σ would have rejected real improvements.
- **Cherry-pick with rewritten message** chosen over fast-forward merge
  to replace the autoloop-generated commit subject (`autoloop exp
  b3-e0-9fb3`) with a descriptive one.

### Infrastructure changes made mid-loop

### Subagent failure mode (root cause analysis)

The spawned `general-purpose` subagent stalled at `ScheduleWakeup` in
both batch 0 and batch 1. Root cause: the subagent has access to
`ScheduleWakeup`, whose docs say it is intended for `/loop` dynamic
mode. When the subagent saw the metric would take ~18 minutes (far
longer than its `Bash` tool's 2-10 min timeout), it reached for
`ScheduleWakeup` as a self-pacing mechanism instead of
`Bash(run_in_background=true)`. That left the agent paused, and the
orchestrator cannot resume a scheduled-wakeup agent without
`SendMessage`, which this Claude Code session does not have in its
tool set.

Template patch applied to
`~/.claude/skills/autoloop/templates/subagent-prompt.md` to explicitly
instruct `Bash(run_in_background=true)` for long metrics and forbid
`ScheduleWakeup`. Untested by a subagent because batches 2-5 were
driven by the orchestrator directly.
